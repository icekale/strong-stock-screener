# 板块雷达精简与成分股分类补全设计

## 目标

1. 从产品界面移除市场热图，仅保留板块雷达与现有独立的汇金持仓追踪入口。
2. 为实时板块成分股补齐行业和当前板块题材，避免列表长期显示“行业待补 / 题材待补”。

## 范围

- 将导航和页面标题“板块与热图”改为“板块雷达”。
- 删除 `MarketView` 中的热图标签、热图请求、热图图表和相关摘要。
- 旧 `/heatmap` 地址兼容跳转到 `/market`，不再展示热图。
- 保留后端热图 provider 和 API。市场概览及行业映射仍依赖这些数据，不在本次删除范围内。
- 前端请求成分股时携带当前板块名称。
- 后端对实时成分股执行一次批量行业查询；查询失败时保留行情响应，不让分类补全拖垮板块页面。
- 实时行没有题材时，以当前板块名称作为题材；已有行业或题材不得被覆盖。

## 数据流

1. 用户选择板块，前端同时提交板块代码和板块名称。
2. 后端从实时板块源读取成分股列表。
3. 后端收集缺少行业的股票代码，调用现有 `market_overview_provider.get_stock_industries` 批量补全。
4. 后端将当前板块名称写入空的 `themes`，并返回补全后的成分股。
5. 行业源不可用时，接口仍返回实时成分股，并通过 `source_status` 标记补全失败。

## 测试

- 后端接口测试：实时成分股能获得批量行业映射和当前板块题材。
- 后端降级测试：行业补全失败时接口仍为 200，已有行情不丢失。
- 前端视图测试：页面不再出现热图入口，也不再调用热图接口。
- 前端请求测试：选择板块时携带对应 `boardName`。
- 路由测试：菜单标题为“板块雷达”，旧 `/heatmap` 跳转 `/market`。

## 非目标

- 不删除后端热图数据模型、provider 或 API。
- 不调整板块强度算法、分时曲线和排序逻辑。
- 不引入新的行业数据源或逐股串行请求。
