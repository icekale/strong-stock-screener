# 缠论结构正确性第一阶段设计

## 背景

当前缠论工作台已经使用 `czsc==0.10.12` 生成分型、笔和官方中枢序列，并暂时关闭了未经验证的线段、背驰和买卖点。现有测试能够证明接口可用、结构不重复和旧数据会被标记为过期，但不能证明图上的端点和中枢位置正确。

本轮审计确认了五个会直接影响图形正确性的问题：

1. 分钟数据只检查最后一根 K 线是否新鲜，不检查中间交易日和分钟是否连续。相隔 28 天的两段完整分钟数据仍可被拼成 `ready`。
2. CZSC 处理包含关系后，适配器仍优先使用原始 bar `id` 查时间。真实 220 日样本中，`300308.SZ` 有 4/17 个笔端点、`600000.SH` 有 5/11 个笔端点映射到错误日期。
3. 个股页主 K 线和缠论结构分别请求两套 bar，横轴可能不同；缠论工作台又使用第三条加载路径。
4. 后端保留了分钟历史回补 API，但 Vue 工作台没有入口；默认最多回补 4,800 根 1 分钟 K，也不足以形成 220 根 60 分钟 K。
5. 中枢映射异常会被转换成空数组，并随 `ready` 响应返回；前端同时仍展示未启用的线段、背驰和买卖点控件。

因此，第一阶段不增加新的缠论能力，只建立能够证明分型、笔和中枢正确的输入、映射、样本和展示契约。

## 目标

1. 只有分钟历史在目标窗口内连续、足量且新鲜时，才允许生成分钟级缠论结构。
2. 分型和笔端点使用 CZSC 完成包含关系处理后的公开时间语义，并精确落到当前响应的 K 线横轴。
3. 用人工复核的固定样本验证分型、笔和中枢的完整坐标，而不只验证数量或不变量。
4. 个股页与缠论工作台对同一标的、周期和回看长度使用完全相同的 K 线序列。
5. 数据不足、历史断裂、映射失败和尚未验证的图层在 API 与 UI 中真实呈现，不能伪装为“无信号”或成功空结果。

## 非目标

- 不增加 15 分钟或 90 分钟周期；支持周期仍为日线、60 分钟、30 分钟和 5 分钟。
- 不实现或重新启用线段、背驰、买卖点、共振信号。
- 不恢复依赖上述未验证结构的预警、回测、选股加分或模拟下单。
- 不改变强势股、竞价 Top3、ETF、情绪、GSGF 或其它业务模块。
- 不以任何商业缠论产品的截图作为唯一正确性标准；本阶段以冻结 K 线、CZSC 公开结构语义和人工审核标签为准。
- 不重做缠论工作台视觉设计，只修复与数据真实性和可用性有关的交互。

## 核心原则

### 失败关闭

结构正确性无法证明时，返回原始 K 线和明确原因，但不返回可消费的结构层。任何异常、缺口或映射歧义都不能降级成 `ready + []`。

### 单一坐标序列

一个分析响应中的 K 线、分型、笔和中枢必须属于同一个 `symbol + period + lookback + adjustment_mode` 数据快照。所有图形坐标都必须能在响应 `bars[].date` 中精确找到。

### 先证明基础结构

分型、笔和中枢通过黄金样本前，不向上构建线段、背驰、买卖点或交易决策。后续能力必须另立规格和验收样本。

## 数据流与所有权

支持周期统一走以下链路：

```text
日线提供方 / TDX 历史 1m / TickFlow 当日 1m
                    |
                    v
          规范化并写入分钟归档
                    |
                    v
       目标窗口连续性与覆盖率审计
                    |
                    v
       仅聚合完整的 5m / 30m / 60m
                    |
                    v
          ChanlunAnalysisResponse.bars
                    |
                    v
       CZSC 包含关系、分型、笔、中枢
                    |
                    v
       个股页与缠论工作台共同渲染
```

`ChanlunAnalysisResponse.bars` 是受支持周期的唯一图表坐标序列。缠论工作台直接使用该字段。个股页在日线、60 分钟、30 分钟和 5 分钟周期也使用该字段绘制主图；原个股 K 线接口只继续提供 GSGF 注释等附加数据，并在缠论分析请求整体失败时作为“不带缠论图层”的降级 K 线。周线不属于本阶段缠论周期，继续使用原个股 K 线接口。

个股页和工作台固定使用相同参数：`lookback=220`、相同复权口径和相同闭合 K 线规则。页面不得把一套响应的结构叠加到另一套响应的 bars 上。

## 分钟连续性契约

### 时间语义

- 所有分钟时间在进入存储前转换为 `Asia/Shanghai`。
- 原始 1 分钟 K 使用区间起点时间：上午 `09:30` 至 `11:29`，下午 `13:00` 至 `14:59`，完整交易日共 240 根。
- TDX 收盘分钟时间继续统一减一分钟，与 TickFlow 的区间起点口径对齐。
- 午休、周末、法定休市日不算缺口。
- 当天只检查 `_expected_latest_close(period, now)` 之前已经闭合的分钟和周期桶。

### 交易日判定

交易所日历负责判断市场是否开市；同一标的的日线记录负责判断该标的在历史开市日是否实际交易。日线记录存在且成交量大于零的日期必须有对应分钟历史。日线明确无交易的停牌日不要求 240 根分钟线。

如果无法取得用于区分停牌与数据缺失的日线参考，则不能证明跨日连续性，覆盖状态为 `unverified`，分钟结构返回 `insufficient_bars`。安全性优先于把不完整数据标记为可用。

### 审计范围

连续性先在未截断的原始分钟归档上执行，再聚合并截取最后 `lookback` 根周期 K。历史连续性窗口从最终入选的最早周期桶所需的第一根原始分钟开始，到最后一根实际可用周期桶结束；窗口外更早的历史缺口不影响本次分析。最后一根实际可用周期桶再单独与 `_expected_latest_close` 比较，以区分“内部缺口”与“历史连续但最新数据尚未到位”。

每个应存在的周期桶必须同时满足：

- 包含精确的 `period_minutes` 根原始分钟 K；
- 时间戳严格递增、无重复、无跨午休聚合；
- OHLCV 全部有效；
- 桶结束时间不晚于当前应闭合边界。

只要目标窗口内存在一个应有但不完整的周期桶，就不能把该窗口标记为 `ready`。两段相隔多个应交易日期的数据不能跨缺口拼接成连续样本。

### 覆盖状态

`ChanlunAnalysisResponse` 增加 `coverage`，最小字段如下：

- `status`: `complete | incomplete | unverified`；
- `required_period_bars` 与 `available_period_bars`；
- `required_raw_minutes` 与 `available_raw_minutes`，日线为 `null`；
- `complete_sessions` 与 `incomplete_sessions`，两者均为非负计数；
- `missing_minutes`；
- `earliest_at` 与 `latest_at`；
- `reason`；
- `backfill_required`。

现有 `availability` 语义保持兼容：

- `ready`：覆盖为 `complete`、最新闭合 K 新鲜、CZSC 计算与映射成功；
- `insufficient_bars`：数量不足、窗口中有缺口，或连续性无法验证；
- `stale`：历史窗口完整，但缺少当前应闭合的最新周期桶；
- `backfilling`：页面已启动该标的回补任务；
- `unavailable`：数据源、CZSC 运行时或结构映射失败。

## 动态历史回补

回补数量由用户请求的周期和回看长度决定，不再固定使用 4,800 根。每个周期所需原始分钟数为：

```text
required_raw_minutes = lookback * period_minutes + 5 * 240
```

额外五个完整交易日用于覆盖当前不完整交易日、分页边界和历史缺口。默认 220 根时：

| 周期 | 基础分钟数 | 含安全余量 |
| --- | ---: | ---: |
| 5 分钟 | 1,100 | 2,300 |
| 30 分钟 | 6,600 | 7,800 |
| 60 分钟 | 13,200 | 14,400 |

工作台回补同时服务三个分钟周期，因此取最大值 14,400。`chanlun_backfill_max_bars` 默认值调整为 16,000，硬上限仍为 24,000。若请求所需数量超过配置硬上限，任务直接失败并返回“所需数量 / 当前上限”，不能写入部分数据后报告成功。

回补请求以 `periods + lookback` 表达目标，默认值分别为全部三个分钟周期和 220 根。现有 `history_days` 改为可选兼容字段：旧客户端传入该字段时，服务根据交易所日历统计最近 `history_days` 个自然日内的开市日数并乘以 240，作为额外的原始分钟数下限；最终请求量取该下限与 `periods + lookback` 计算值的较大者。任何计算结果超过硬上限都在拉取前明确失败。后台任务按 TDX 每页 800 根拉取、规范化、幂等写入、重新执行覆盖审计，并在完成后清除闭合输入与分析缓存。成功结果至少返回写入数量、请求数量、各周期覆盖状态和缺口统计。

工作台在 `coverage.backfill_required=true` 时显示“补齐分钟历史”命令。命令启动现有后台任务、轮询进度，完成后重新读取当前周期与工作区。回补失败保留原始 K 线，并显示失败原因，不自动重复请求。

## CZSC 时间映射

当前 `dates_by_id` 方案不再用于决定结构时间。CZSC 在包含关系处理后生成的对象，其公开 `dt` 才是结构端点的时间语义：

- 分型使用 `FX.dt`；
- 已完成笔起终点使用 `BI.fx_a.dt` 和 `BI.fx_b.dt`；
- 观察笔端点使用未完成结构中对应极值 bar 的 `dt`；
- 所有 native `dt` 先按 `Asia/Shanghai` 解释或转换，再输出带 `+08:00` 的秒级 ISO 时间。

映射后的时间必须与当前 `ChanlunAnalysisResponse.bars[].date` 精确相等。禁止按相邻日期、数组下标或最近 K 线猜测。端点价格必须是 CZSC 对应分型价格，方向必须与原生 BI 方向一致。任一端点无法精确映射时，整个结构分析返回 `unavailable`，同时保留 bars 和简短映射错误；不能跳过该端点继续发布残缺结构。

结构 ID 由规范化后的时间、方向和价格稳定生成。相同输入重复计算必须得到相同 ID。

## 中枢映射与异常语义

确认中枢继续以 `czsc.utils.sig.get_zs_seq(native.finished_bis)` 为唯一来源，不恢复滑动三笔近似算法或虚中枢。

中枢必须满足：

- 至少包含三笔，且 CZSC `is_valid` 为真；
- `low=zd`、`high=zg`，且 `high >= low`；
- 开始时间为中枢第一笔的开始，结束时间为最后一笔的结束；
- 中枢引用的每一根 native BI 都有已成功映射的项目笔；
- 同一输入中不存在完全相同的起止时间与价格区间。

`get_zs_seq` 抛错、返回无法映射的 BI、出现非有限价格或非法区间时，抛出明确的结构映射错误，由适配器转换为 `availability=unavailable`。只有 CZSC 正常返回空序列时，`ready + zones=[]` 才表示“当前确实没有确认中枢”。

## 黄金样本

### 文件与内容

黄金样本保存在 `apps/api/tests/fixtures/chanlun/golden/`。每个 JSON 文件包含：

- `schema_version`、`symbol`、`period`、`lookback`；
- `source`、`adjustment_mode`、`czsc_version`、`rule_version`；
- 完整、有序的输入 `bars`；
- 期望 `fractals`、`strokes` 和 `zones` 的全部时间、价格、方向与状态；
- 每个确认结构首次可见的 `confirmed_at`；
- `reviewed_by`、`reviewed_at`、`review_status=approved` 和审核说明。

测试拒绝缺少审核元数据或 `review_status` 非 `approved` 的样本。期望结构必须冻结在文件内，测试运行时不得用当前适配器重新生成期望值。

### 初始样本矩阵

第一阶段至少包含：

1. 人工构造的包含关系样本，专门验证合并 K 线后的分型和笔端点时间；
2. `300308.SZ` 的 220 根日线真实冻结样本；
3. `600000.SH` 的 220 根日线真实冻结样本；
4. 上述两个标的各一份 220 根 60 分钟真实冻结样本。

真实样本应覆盖上涨笔、下跌笔、连续包含关系和至少一个确认中枢。如果某一时间窗口没有确认中枢，调整冻结窗口，不能以空中枢样本替代中枢验收。

### 审核与断言

人工审核按原始 K 线逐项确认分型高低点、相邻笔起终点和中枢三笔重叠区，并在审核说明中记录争议处理。自动测试要求：

- 时间、方向、状态和结构顺序完全一致；
- 分型与笔价格误差不超过 `1e-6`；
- 中枢上下界误差不超过 `1e-6`；
- 输出中不得多出或缺少任何确认结构；
- 从序列开头逐根截断重放时，结构不得早于 `confirmed_at` 出现；确认后再次重放时，其 ID 和坐标不得变化。

只有全部黄金样本通过后，规则版本才从 `cl-v2-visual` 提升为 `cl-v3-validated`。

## API 与 UI 行为

### API

- `GET /api/chanlun/stocks/{symbol}/analysis` 返回 canonical bars、coverage 和经过验证的分型、笔、中枢。
- `GET /api/chanlun/stocks/{symbol}/workspace` 的日线分析和各周期摘要来自同一闭合输入快照。
- `POST /api/chanlun/stocks/{symbol}/backfill` 接收 `periods` 与 `lookback`，兼容 `history_days`，并真实使用请求参数。
- `GET /api/chanlun/stocks/{symbol}/backfill/{job_id}` 返回可展示的进度与最终覆盖结果。

API 仍保留 `segments=[]`、`divergences=[]`、`signals=[]` 以兼容客户端，但 `source_status` 明确标记这些图层为 `disabled`。

### 缠论工作台

- 分型、笔和中枢仅在 `availability=ready` 时可开启。
- 线段、背驰、买卖点固定禁用，并显示“尚未通过黄金样本验证”，不能显示为数量 0 或“无信号”。
- 数据断裂或不足时展示覆盖摘要、缺口数量和回补命令；回补中展示真实任务进度。
- 修正周期摘要字段，读取 `latest_signal` 和 `latest_divergence`；在本阶段二者显示“未启用”，而不是错误地读取不存在的 `latest_signal_type`、`latest_divergence_type`。
- 映射失败时保留 K 线，清空并禁用全部缠论图层，展示“结构映射失败”。

### 个股页

- 日线、60 分钟、30 分钟、5 分钟主图优先使用当前缠论分析响应的 canonical bars。
- 只有结构响应与 canonical bars 属于同一请求时才叠加图层。
- 缠论请求失败时可使用原 K 线接口降级显示价格，但必须关闭缠论图层并展示原因。
- 周线保持现状，不伪造周线缠论结构。

## 测试与验收

### 后端单元测试

- 两个完整交易日相隔 28 天且中间存在该标的日线记录时，覆盖为 `incomplete`，分析不得为 `ready`。
- 单个历史交易日缺一分钟时，对应 5/30/60 分钟目标窗口均不跨缺口拼接。
- 午休、周末、休市日和日线确认的停牌日不计为缺口。
- TDX 与 TickFlow 相同交易分钟写入后使用同一时间戳且不重复。
- 220 根 60 分钟 K 的回补目标为 14,400 根原始分钟 K；默认硬限制能够满足该请求。
- 回补请求超过硬限制时，在写入前明确失败。
- 包含关系样本中的分型和笔端点精确等于 native `dt` 对应的 canonical bar。
- native 时间不在 canonical bars、中枢引用未映射 BI、`get_zs_seq` 异常时均返回 `unavailable`，不能返回成功空结构。
- 四份真实黄金样本和一份人工包含关系样本逐项完全通过。
- 每份黄金样本通过逐 bar 截断测试，不出现提前确认或确认后漂移。

### API 与前端测试

- 分析和工作区响应包含一致的 coverage、bars 和规则版本。
- 回补 API 使用 `periods`、`lookback` 或兼容字段，不再丢弃请求参数。
- 工作台能启动和轮询回补，成功后重载；失败后展示原因。
- 个股页与工作台对相同查询渲染相同 bars 时间序列。
- 结构不可用时原始 K 线仍显示，但没有任何缠论 overlay。
- 未验证图层的按钮、指标卡和周期摘要均明确显示禁用状态。

### 完整验证

实现完成后运行全部后端 pytest、Ruff、全部前端 Vitest、Vue typecheck 和生产构建。另对 `300308.SZ` 与 `600000.SH` 运行冻结样本报告，报告列出 bar 数量、分钟覆盖、分型/笔/中枢精确匹配数量、截断稳定性和规则版本。

## 发布边界

第一阶段完成的定义是：受支持周期在连续数据上稳定绘制通过人工黄金样本验证的分型、笔和确认中枢；数据不满足条件时明确关闭结构层；个股页和工作台不再混用横轴。

线段、虚中枢、背驰、买卖点、预警、选股加分、回测和模拟下单继续保持关闭。它们只有在各自独立规格、黄金样本和无未来函数测试完成后才能重新启用。
