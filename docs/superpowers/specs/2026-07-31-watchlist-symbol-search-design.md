# 自选股股票搜索修复设计

## 背景

自选股页面的“加入自选”控件目前是普通文本输入框。它不会调用已有的股票搜索接口，也没有候选列表；提交时会把代码、中文名称或字母缩写原样当作证券代码。现有后端搜索接口能够按标准代码和中文名称匹配，但不支持全拼或拼音首字母。

## 目标

1. 用户输入证券代码、中文名称、全拼或拼音首字母时，显示可选择的 A 股候选。
2. 候选项统一展示股票名称和标准代码，选择后再加入自选。
3. 写入自选池时同时保存标准代码和股票名称。
4. 搜索接口失败或输入无法匹配时，不把原始中文或拼音误写为证券代码。

## 非目标

- 不重做自选股分组、标签和批量文本编辑。
- 不改变自选池文件格式或已有股票记录。
- 不新增模糊纠错、同音字搜索或证券类型扩展；本次只处理 A 股代码表。
- 不修改缠论结构、预警或镜像精简逻辑。

## 后端设计

继续复用现有股票代码表缓存和搜索响应模型。股票表加载时为每只股票生成两个内部检索键：不带声调的全拼和拼音首字母；这些键不进入公共 API 响应。

匹配不区分大小写，排序优先级为：

1. 标准代码或六位代码完全匹配；
2. 代码前缀匹配；
3. 中文名称完全匹配或前缀匹配；
4. 拼音首字母完全匹配或前缀匹配；
5. 全拼前缀匹配；
6. 代码、名称、首字母或全拼的包含匹配。

同一标准代码只返回一次。远程代码表失败时继续使用自选池和最近选股结果中的本地记录，并在 `source_status` 中保留失败原因。拼音转换使用轻量依赖 `pypinyin`，在代码表构建时执行，不在每次按键时遍历转换。

## 前端设计

将自选股页面的普通输入框替换为远程搜索选择器：

- 输入非空文本后进行短延迟搜索，避免每个按键同时发起请求；
- 下拉项展示“名称”和“标准代码”；
- 只允许已选择的候选进入新增请求；
- 选择后可按 Enter 或点击“加入自选”；
- 请求携带候选的 `symbol` 和 `name`，成功后清空选择并刷新列表；
- 新查询会使旧查询结果失效，防止慢响应覆盖较新的输入；
- 搜索失败显示页面级提示，空结果显示“未找到匹配股票”。

批量文本编辑和“保存股票池”保持现状。

## 测试与验收

后端测试覆盖：代码、中文、全拼、大小写首字母、匹配排序、去重以及远程数据源失败时的本地降级。

前端测试覆盖：输入触发搜索、候选内容、选择后提交标准代码和名称、无选择时不提交、旧响应不会覆盖新查询、接口错误可见。
